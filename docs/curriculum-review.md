# Curriculum Review

This review assesses the current public writing-track catalog as a pedagogical system, not just a product menu.

The current catalog is structurally coherent:

- 17 public tracks
- 52 TGOs per public track
- strong reuse of shared skills across tracks
- enough breadth for cross-track transfer

It is not yet fully comprehensive as a long-term writing curriculum.

## What The Catalog Already Does Well

The current public catalog covers several major writing families well:

- fiction and genre fiction
- essayistic and public-facing nonfiction
- workplace and professional communication
- instructional, technical, and academic writing
- grant, persuasive, and memoir writing

This is a stronger foundation than a typical single-track writing app because it already supports transfer between paths. The shared taxonomy confirms that many skills recur across tracks instead of being rebuilt from scratch.

Examples from the live catalog:

- `revision habits` appears in all 17 public tracks
- `audience alignment` appears in 13 public tracks
- `clarity and coherence` appears in 10 public tracks
- `structural signposting` appears in 10 public tracks
- `evidence integration` appears in 9 public tracks

That is the right direction. Writing education works better when students feel that one path compounds another.

## What Feels Missing

The catalog is strongest in prose. The biggest curricular gaps are writing domains that depend on materially different craft moves rather than just different subject matter.

Most important missing public domains:

- poetry / verse
- scriptwriting / playwriting / screenwriting
- speechwriting / oral rhetoric
- UX writing / product microcopy

Possible second-wave additions:

- writing for children / middle grade / YA as a public path
- legal / policy / civic writing
- newsletter / creator essay writing if audience demand exists

These are worth adding because they are not just topical variants of existing tracks. They rely on different constraints:

- poetry depends on lineation, sound, compression, image logic, and stanza movement
- scriptwriting depends on scene beats, visual exposition, dramatic turns, and subtext in dialogue
- speechwriting depends on oral cadence, memory lines, repetition, escalation, and audience energy
- UX writing depends on task clarity, error-state guidance, information scent, and tone under hard space constraints

## Where Variety Should Live

The current system should not immediately expand into dozens of top-level tracks.

A better model is:

- keep a moderate public catalog of domain tracks
- add specialty arcs inside or alongside those tracks
- let users combine multiple tracks and earn transfer on shared skills

That preserves finishability while still increasing variety.

The fiction family already suggests the right pattern:

- a broad story craft base
- genre overlays for fantasy, science fiction, romance, literary fiction, and mystery / thriller

That same idea should be applied elsewhere. Some future additions should be full tracks, but many should be specialty layers.

Good candidates for specialty arcs rather than entirely separate public domains:

- investigative journalism
- startup / executive communication
- nonprofit fundraising strategy
- longform essay
- conversion copy
- personal essay

Good candidates for genuinely distinct public tracks:

- poetry
- scriptwriting
- speechwriting
- UX writing

## Are 52 TGOs Per Track Enough?

Yes, if those 52 TGOs are treated as developmental dimensions rather than one-time boxes to check.

Fifty-ish nodes is enough for a finishable main path if:

- the same skill reappears in harder contexts
- assignment types vary across the same skill
- users can continue into adjacent tracks and carry shared mastery forward
- finishing means solid foundational command, not total mastery

Fifty-ish nodes is not enough if the app implies:

- one pass per skill
- permanent completion after a single successful attempt
- no layered practice or cross-track reuse

The current size is pedagogically reasonable. In fact, it is probably better than making each track much larger. Writers benefit from visible completion. An endless tree tends to weaken motivation and blur what progress means.

Recommended target:

- main tracks: 40-60 TGOs
- specialty arcs: 8-15 TGOs
- advanced capstones or remix clusters after track completion

## Shared Skills vs Specialty Skills

The current shared-skill pattern is promising and should be strengthened.

From the live catalog:

- many skills already recur across 6-17 tracks
- only a small set currently appear in exactly one track

Current rare skills:

- `accuracy`
- `example quality`
- `reflection depth`
- `technical precision`
- `user goal alignment`
- `voice presence`

This suggests two things:

1. The catalog already behaves more like a shared curriculum than a bespoke-track system.
2. Some rare skills are likely valid specialties, but others may deserve broader reuse.

In particular:

- `technical precision` should probably remain narrow
- `user goal alignment` is a strong technical / UX / instructional domain skill
- `reflection depth` belongs mostly in memoir and personal essay
- `voice presence` may deserve broader use in thought leadership, literary fiction, and speechwriting
- `example quality` should likely expand into educational writing, technical writing, and content marketing
- `accuracy` may become more important if journalism, technical writing, and policy writing are deepened

## Recommended Catalog Direction

Near-term public catalog recommendation:

- keep the current 17 public tracks
- add 4 missing high-value public tracks over time:
  - poetry
  - scriptwriting
  - speechwriting
  - UX writing

Curriculum architecture recommendation:

- keep universal shared skills as the base lattice
- keep domain skills reusable across related families
- allow only a small number of true specialty skills per track
- avoid bespoke skill vocabularies for every path

Progression recommendation:

- keep tracks finishable
- unlock specialty arcs after or during later track stages
- give users visible transfer credit when they enroll in adjacent tracks

## Concrete Design Principles For Next Regeneration

When regenerating tracks, use these rules:

- every public track should still start with 2 core seeds and 1 domain seed
- most TGOs should map to shared core or domain skills
- each track should use specialty skills sparingly
- each track should feel mission-aligned through sequencing and exercise context, not through a bespoke vocabulary
- advanced variety should come from elective branches more often than from new top-level tracks

## Bottom Line

The current approach is closer to the right product shape than an open-ended menu of tiny bespoke tracks.

The system should feel finishable, but not exhaustible:

- finishable main paths
- shared mastery across tracks
- specialty branches for advanced choice
- a few genuinely distinct missing domains added over time

That will give users both momentum and longevity without turning the curriculum into a cluttered catalog.
